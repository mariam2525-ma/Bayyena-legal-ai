## 1. Test Plan & Verification Methodology
Our quality assurance strategy combines automated verification in the repository with honest live testing on the deployed production URL (`https://mohakem-contract-platform.vercel.app/`):
1. **ESLint & Syntax Verification (`npm run lint:js`)**: Runs `eslint` (`.eslintrc.json`) and `node --check` (`scripts/check-syntax.js`) across all frontend JavaScript modules (`js/00-errlog.js` through `js/09-bootstrap.js`, `js/config.js`, `js/policy.js`).
2. **Code Formatting Verification (`npm run format:check`)**: Runs Prettier / `scripts/check-format.js` (`.prettierrc.json`) across all frontend JS files.
3. **Workflow & Secret Audit (`npm run lint:json`)**: Executes `scripts/validate-workflows.js` across all **8 n8n workflows** (`n8n/01-support-desk.json` through `n8n/08-web-search.json`), verifying valid JSON structure, webhook path definitions, empty `pinData: {}`, zero JWT tokens (`/eyJ[A-Za-z0-9_-]{20,}.../`), and zero personal email addresses.
4. **Automated Smoke & XSS Unit Suite (`npm test`)**: Executes **9 automated tests** in `tests/smoke.test.js` verifying application boot, Arabic RTL DOM + `#trialBanner`, HTTPS webhook endpoints, `esc()`, every `innerHTML` path (`render()`, `pick()`, `fld()`, `show()`), 8 workflows inventory, database SQL files (`01`..`04`), disabled external search checkboxes (`#web`, `#xw`, `#cw`), absence of unverified 30-day auto-deletion claims, and SHA-256 integrity of `assets/policy.pdf`.
5. **Live Browser Verification (`TC-01`…`TC-20`)**: Executed directly against `https://mohakem-contract-platform.vercel.app/` and `#diag`. In strict compliance with project QA rules, **only test cases actually executed and verified carry `PASS`**; test cases blocked by live authentication/credentials are explicitly marked **`لم يُنفَّذ`** with the exact reason, and discrepancies found on the live deployment are logged as **`FAIL`** with full bug reports and reproduction steps.

## 3. Bug Reports & Reproduction Steps

### Bug #1 (Fixed in `v1.1.0`): Large Digital PDF Books Truncating During Knowledge Ingestion
- **Severity:** High
- **Symptom:** Uploading *ترجمة العقود المدنية — د. مصطفى محمد المرشدي* (6.7 MB PDF) to the original 11-node ingestion workflow sent the entire PDF to Gemini OCR in a single call, hitting `MAX_TOKENS` and indexing only 1 chunk.
- **Resolution:** Updated `n8n/07-knowledge-ingest.json` (14 nodes) to run `Extract PDF Text` → `Has Text Layer?` (`text.length >= 200`) → `Classify Text Layer` before falling back to `Gemini Flash OCR & Classify`, adds a digital-text extraction route before OCR fallback. Historical documentation described a corpus size, but row data is excluded from this package and no live rows were queried; ingestion/count claims are not treated as current verified data.

### Bug #2 (Fixed in `v1.1.0`): Asynchronous Review/Drafting Jobs Stuck in `pending` Status
- **Severity:** High
- **Symptom:** Unhandled Gemini errors mid-pipeline left `review_jobs.status = 'pending'`, causing `hookAsync()` polling to wait until timeout.
- **Resolution:** Added `retryOnFail: true, maxTries: 2` and wired error outputs to a dedicated `Processing Error` node in workflows `02`, `03`, `04`, and `06`, plus added `database/02-fix-stuck-jobs.sql`.

### Bug #3 (Fixed in `v1.1.1`): Unescaped `r.level` in `render()` (`js/02-tool.js`) Allowing Attribute/HTML Injection
- **Severity:** High (Security / XSS)
- **Steps to Reproduce:**
  1. Inspect `js/02-tool.js` line 279 in `v1.1.0`: `'<span class="lv ' + r.level + '">'`.
  2. Pass a risk object where `r.level` contains `'h"><img src=x onerror=alert(1)>'` and call `render()`.
  3. Observe that `r.level` is concatenated directly into `#rl.innerHTML` without `esc()`.
- **Resolution (`v1.1.1`):** Wrapped `esc(r.level)` in `render()`, wrapped `esc(s)` in `run()`, wrapped `esc()` around all parameters of `fld(n, l, g, ty)` in `js/05-drafting-chat.js`, and added automated regression tests (Tests #7 and #8 in `tests/smoke.test.js`).

### Bug #4 (Fixed in `v1.1.1`): Leaked Personal Email & Non-Empty `pinData` in Workflow Exports and Git History
- **Severity:** High (Security / Privacy)
- **Steps to Reproduce:**
  1. Run `grep -rn "mariamhan504\|pinData" n8n/` or inspect raw `My workflow.json` in `v1.1.0`.
  2. Observe `[redacted-email]` in `n8n/01-support-desk.json` (lines 180 and 286), non-empty `pinData` in `01`, `03`, `04`, `06`, and a real user JWT (`eyJ...`) in raw `My workflow.json`.
- **Resolution (`v1.1.1`):**
  1. Added cleaned `n8n/08-web-search.json` (19 nodes, `pinData: {}`, zero tokens/emails) instead of raw `My workflow.json`.
  2. Replaced hardcoded email in `n8n/01-support-desk.json` with `={{ $env.SUPPORT_EMAIL || 'support@muhkam.local' }}` and cleared `pinData: {}` across all 8 workflows.
  3. Scrubbed git history across all branches and tags (`git filter-branch`) and updated `scripts/validate-workflows.js` to fail the build on any non-empty `pinData`, JWT, or personal email.

### Bug #5 (Fixed in `v1.1.1`): Inaccurate Statutory Citations in `v1.1.0` Documentation (Civil Code art. 558+ and Law 4/1996 & Civil Code arts. 418 and 447+ and Traffic Law 66/1973)
- **Severity:** Medium (Legal Accuracy)
- **Steps to Reproduce:**
  1. Open `docs/TESTING_AND_QA.md` (TC-06, TC-10) and `docs/USER_MANUAL.md` (Section 2) in `v1.1.0`.
  2. Observe that `TC-06` cited Law No. 164 of 2025 as a basis for reviewing a new residential lease, and `TC-10` cited Consumer Protection Law No. 181 of 2018 for a used car sale between individuals, while the old PDF user manual referred to "5 tools" ("الأدوات الخمس") and "7 workflows".
- **Resolution (`v1.1.1`):** Corrected all documentation (`README.md`, `ARCHITECTURE.md`, `API.md`, `USER_MANUAL.md`, `TESTING_AND_QA.md`, `PROJECT_DESCRIPTION.md`, and `Muhkam_Documentation_and_QA_Report.pdf`) to state **4 services + Muhkam assistant** and **8 workflows**, and to clarify that new residential leases between individuals are governed by the **Egyptian Civil Code (Art. 558 et seq.) and Law 4/1996** (whereas Civil Code art. 558+ and Law 4/1996 applies only to old-rent leases under Laws 49/1977 & 136/1981) and private used car sales between non-professional individuals are governed by the **Egyptian Civil Code (Art. 418, 447 et seq.) and Traffic Law 66/1973** (not Consumer Protection Civil Code arts. 418 and 447+ and Traffic Law 66/1973).
