## حدود ما يثبته الرسم

الرسم ليس DDL كاملًا. قد يعرض رموز مفاتيح وخطوط علاقات، لكنه لا يثبت جميع تعريفات PK/FK أو سلوك ON DELETE أو defaults أو الفهارس أو سياسات RLS أو grants أو تعريفات الدوال أو بُعد vector أو migrations قابلة لإعادة التشغيل. لا يثبت سلوك RLS بين الحسابات.

إفادة المالكة باختبارها هي ومُنى لفصل الحسابات على الواجهة، واختبارات الفريق لرفع الملفات خارج التسجيل، أدلة يدوية منسوبة للفريق كما في QA؛ لا تُنفى هنا ولا تُنسب إلى الصورة أو إلى فحص DB/API مستقل.

تظل 7b **PARTIAL/جزئي بدليل بصري مكمل**. فجوة CREATE POLICY في `database/01-schema.sql:90-102`، وفروق أسماء الفهارس وحد 12 نتيجة بين تقرير metadata والمسودة، وعدم وجود migrations مثبتة قابلة لإعادة التشغيل، لا تُغلق بهذه الصور. راجع `docs/SUPABASE_LIVE_STRUCTURE.md`.

لم يُعدّل مخطط Supabase أو إعداداته أو بياناته، ولم يُطبق SQL. هذا تحديث أدلة وتوثيق فقط.

## صادرات SVG الإضافية المرسلة لاحقًا

قورنت الصادرات `(1).svg` و`(2).svg` و`(3).svg` و`(5).svg`، وكلها بحدود عرض 1285×716. الأول يتضمن جداول بأسماء مثل `oauth_clients` و`webauthn_credentials`؛ الثاني `messages` و`schema_migrations` و`subscription`؛ الثالث جداول بأسماء مثل `buckets` و`objects`؛ والخامس `secrets`. لا يتضمن أي ملف أسماء جداول محكم العامة المطلوبة: `bayyena_knowledge` و`history` و`review_jobs` و`support_tickets`. لا يُستنتج من ذلك اختلاف المشروع نفسه؛ الملفات لا تعرض المخطط العام المطلوب. سجل المقارنة والبصمات في `SVG_EXPORT_REVIEW.json`.

لذلك لا يُقبل تحويل أي منها كـPNG كامل لتلك الجداول، ولا تُستكمل الجداول الغائبة بالتخمين أو إعادة الرسم. تُحفظ الملفات الأصلية وتفاصيل فحصها ضمن أدلة الحزمة للمراجعة، وليس كمرجع DDL أو كبديل كامل للصورتين. يبقى المطلوب تصديرًا جديدًا باختيار `Schema=public` والجداول العامة المطلوبة ثم Fit view من لوحة Supabase؛ هذا التصدير لم يُنجز هنا، ومعيار 7b ما زال جزئيًا.
